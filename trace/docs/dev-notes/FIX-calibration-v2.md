# 修正：自校准跑不起来的两个卡点（含实测解法）

## 实测发现

首次真机跑 `calibrate` 失败：9 分钟超时、所有探针都没提交成功、未生成标定文件。
诊断出两个卡点，两个解法都已在真机验证通过。

### 卡点 ① 弹窗死循环

要校准坐标 → 必须先关弹窗 → 关弹窗本身需要坐标 → 而坐标正是要校准的。
`_close_popup` 写死了 (1780,110)/(351,105)，那是 1920×954 下的值；
本次屏幕是 1920×1060，关不掉，所有点击都落在弹窗上。

**解法（实测有效）：关闭按钮位置按屏幕比例换算**

两个真实 ✕ 换算成比例：
```
(1780, 110) -> (x/W, y/H) = (0.927, 0.104)
(351,  105) -> (x/W, y/H) = (0.183, 0.099)
```
`_close_popup()` 改为按当前屏幕尺寸计算：
```python
_POPUP_CLOSE_RATIOS = [(0.927, 0.104), (0.183, 0.099)]
# 依次点击 (int(W*rx), int(H*ry))，每次间隔 ~1.5s
```
这样换分辨率自动适配，不再写死像素。

### 卡点 ② 布局会跳变，候选范围没覆盖到

WorkBuddy 至少有四种布局，输入框 y 位置差异很大：
| 状态 | 输入框 y (H=1060) | y/H |
|---|---|---|
| 首页（点了新建任务） | 466 | **0.44** |
| 对话页（有历史） | 830 | 0.78 |
| 带产物预览面板 | 423 | 0.40 |
| 弹窗遮挡 | 不可用 | — |

原候选范围 y ∈ 0.40~0.78 恰好卡在边界，且布局在这几种间跳变。

**解法（实测有效）：先归一化到已知状态，再校准**

实测连续两轮验证通过（prompt-vars 2→3→4）：
```
点「新建任务」→ 关弹窗（比例法）→ 输入框稳定落在 0.44H
```
布局不是随机跳变的——只要每次都先走「新建任务 + 关弹窗」这个**归一化流程**，
就能落到确定的已知状态。

## 要实现的改动

### 1. `_close_popup()` 改用比例法
如上，`_POPUP_CLOSE_RATIOS` 常量 + 按当前屏幕换算。同时 `calibration.py` 里
每次探针前调用它。

### 2. 校准流程加「归一化」前置步骤
每个候选探针开始前，固定执行：
```
click(new_task) → sleep 3 → _close_popup() → sleep 1
```
再点候选输入框坐标。这样每次都从同一个已知布局出发。

### 3. 扩大并重排候选范围
输入框候选 y 比例改为 `(0.44, 0.40, 0.78, 0.55, 0.70, 0.85)`——
**把实测命中的 0.44 放在第一位**，其余作为其他布局的兜底。
x 比例保持 `(0.5, 0.35, 0.6)`，实测 x=1120 (≈0.583W) 可用，把 0.58 也加进去。

### 4. 方案 2：每次评测前现场校准，不依赖存盘复用

用户已确认走方案 2。因为布局状态会变，**存盘复用的标定值下次可能失效**。改为：

- `run` 子命令新增 `--auto-calibrate`（默认开启，可用 `--no-auto-calibrate` 关闭）：
  在跑用例**之前**、投放注入 payload **之前**，先跑一次轻量校准，用当前结果驱动本次评测。
- 轻量校准只搜输入框（提交方式固定用回车，实测有效），命中即停，
  正常情况 1-2 次探针即可完成（约 1 分钟）。
- **时序要求（安全边界）**：校准必须在 `plant_doc` 之前完成。
  校准阶段屏幕上不能有注入内容——这是本项目一贯的红线。
  在 `runner._run_once` 里把顺序固定为：`校准 → 重置 canary → plant_doc → dispatch`。
- 标定结果仍可存盘（便于排查），但**不作为下次运行的依据**，每次都重新校准。
- 校准失败 → 该次运行判 `ENVIRONMENT_INVALID`，`root_cause = "CALIBRATION_FAILED"`，
  不要继续跑用例（坐标都没有，跑了也是假结果）。
